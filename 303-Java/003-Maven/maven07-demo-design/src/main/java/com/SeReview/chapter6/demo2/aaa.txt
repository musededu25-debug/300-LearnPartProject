你原来的三个文件：

public void show(String name){ System.out.println(name); }   // 参数名撞了字段名

5. 核心结论（这次的真正收获）

▎ super 不是「另一个对象」，是「本对象内部属于父类的那一半」。
▎ 所以 new Child("lisi") 里的 super.name 永远是 lisi，跟那个 new Father("zhangsan")
▎ 没有半点关系。
▎ 补充推论：你原来那份没写 super(name) 的代码，如果编译得过，super.name 会打印 null —— 既不是
▎ zhangsan 也不是 lisi。这反过来证明了 super 读的是「自己这个对象」。

二、留给你的五道练习（1.5 构造执行顺序）

统一约束
- 放在 maven07-demo-design/src/main/java/com/SeReview/chapter6/demo2/，一题一个文件。
- 所有输出必须由真实的初始化过程产生——不许在 main 里手写 println 凑顺序。
- 先写下预期输出再运行。这道题的价值全在「预测 vs 实际」。

练习 1 · 把六步走全

Base / Sub（Sub extends Base），main 里只 new Sub(); 一次，输出恰好是：

Base 静态字段
Base 静态块
Sub 静态字段
Sub 静态块
Base 实例字段
Base 实例块
Base 构造体
Sub 实例字段
Sub 实例块
Sub 构造体

▎ 字段要打印字符串可以写 static int init(String s) { System.out.println(s); return 1; }。

练习 2 · this(...) 链

Base 有 Base() / Base(String)；Sub 有 Sub() / Sub(String)，且 Sub() 第一条语句写
this("默认值")。main 里只 new Sub();。

要求输出能证明三件事：① 两个子类构造里只有最终那个调了父类构造；②
父类构造体在所有子类成员初始化之前；③ this(...) 的执行位置在父类构造之后、子类构造体之前。

练习 3 · 反推书写顺序

A / B（B extends A），main 里只 new B();，输出恰好是：

A 静态块
A 静态字段
B 静态字段
B 静态块
A 实例字段
A 实例块
A 构造体
B 实例块
B 实例字段
B 构造体

▎ 考点：在 A 里让静态块排在静态字段前、在 B 里反过来——决定这个顺序的是什么？B
▎ 的实例块排在实例字段前，同一套规则在实例层面还成立吗？为什么 B 的静态输出全挤在 A
▎ 的实例输出之前？

练习 4 · 复现坑 4（关键）

Father 的构造方法体里调用一个被子类重写的方法，子类里有 int value = 100;。new Child();
的输出恰好是：

Child.print, value=0

▎ 写完后用注释回答：为什么是 0 而不是 100？ 要用 1.5 的顺序说清「它卡在第几步、被谁抢先了」，不许写「因为字段还没初始化」这种话。

练习 5 · 触发时机

写类 T，含静态块（打印 T 初始化了）和 static int COUNT = 1;。main 里依次：① 打印 还没碰过 T；② 声明一个 T 类型变量但不 new；③ 读一次 T.COUNT；④ 再读一次 T.COUNT，然后 new T() 一次。

输出恰好只有两行：

还没碰过 T
T 初始化了

▎ 考点：哪一步触发了类初始化？为什么第 ④ 步的 new T() 没让「T 初始化了」再打印？如果第 ② 步就打印了，说明你写错了什么？
